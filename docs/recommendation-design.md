# NaengCook 레시피 추천 설계 (MVP 초안 v0.1)

작성일 2026-11-04. 백엔드 내부 설계 문서. DB/규칙 기반 추천의 알고리즘·정책·상수를 정의한다.
API 응답 형태는 [`api-spec.md`](./api-spec.md)의 `GET /recommendations` 참고. 구현 전 설계 단계이며 코드는 포함하지 않는다.

## 알고리즘 파이프라인

```
1. 보유 재료 조회 (+ 임박 판정: daysLeft ≤ 3)
2. 후보 선정: 보유 재료를 1개 이상 쓰는 레시피만   → 보유 0개 레시피는 진입 전 제외
3. 제외 필터: 부족 재료가 전체 필요 재료의 50% 이상 → 삭제
4. 점수 계산:
     score =  w1 · (임박 재료 활용)
            + w2 · (보유 재료 일치도)
            − w3 · (부족 재료 패널티)
5. score 내림차순 정렬 → 반환
```

## 상수 (확정값, 튜닝 대상)

| 상수 | 값 | 의미 |
|---|---|---|
| 임박 기준 | `daysLeft ≤ 3` | 이 이하면 "임박 재료" |
| w1 (임박 활용) | 3 | 1순위 가중치 |
| w2 (보유 일치도) | 2 | 2순위 가중치 |
| w3 (부족 패널티) | 1 | 3순위 가중치 |
| 감점 유예 | 부족 ≤ 3개 | 이하면 감점 없음 |
| 제외선 | 부족 ≥ 전체의 50% **또는 보유 0개** | 후보에서 삭제 |

상수는 목업 데이터로 돌려보며 튜닝한다.

### 가중치 해석 시 주의점

- **확정값이 아니다:** w1/w2/w3(3, 2, 1)은 목업 데이터로 튜닝할 초기값이다.
- **가중치가 크다고 항상 우선되지는 않는다:** 개수로 계산하면 임박 재료 1개는 3점(`3×1`)이지만 보유 재료 2개는 4점(`2×2`)이므로, 임박 재료를 쓰지 않는 레시피가 더 높은 점수를 받을 수 있다.
- **수치화 방식을 먼저 정해야 한다:** "임박 재료 활용"과 "보유 재료 일치도"를 개수로 셀지 비율로 셀지에 따라 가중치의 실제 영향력이 달라진다. 튜닝 전에 이 방식을 확정한다(열린 항목 참고).

## 두 개의 손잡이: 제외(%) vs 감점(개수)

부족 재료를 다루는 장치는 **단위가 다른 두 가지**이며 서로 독립이다.

- **제외(1차 필터) — 퍼센트 기준.** 레시피 크기에 공평하게 "절반 이상 없으면 버린다".
- **감점/무감점 — 개수 기준.** 사람 체감에 맞게 "4개나 없으면 깎는다".

순서: 제외 필터를 먼저 통과한 레시피만 감점 계산으로 넘어간다.

### 감점 공식

```
부족 ≤ 3개  → 감점 0 (유예)
부족 ≥ 4개  → 감점 = w3 × (부족개수 − 3)
```

부족분에 **비례**해 깎인다(ON/OFF 아님). `−3`을 쓰는 이유는 3→4 경계에서 점수가 급락하지 않고 매끄럽게 증가시키기 위함.

### 경계 예시 (필요 재료 20개 기준)

| 부족 | 판정 | 비고 |
|---|---|---|
| 0~3개 | 통과, 감점 0 | 유예 구간 |
| 4개 | 통과, 감점 −1 | `1×(4−3)` |
| 5개 | 통과, 감점 −2 | `1×(5−3)` |
| 9개 | 통과, 감점 −6 | `1×(9−3)`, 많을수록 큰 감점 |
| 10개 | **제외** | 10/20 = 50% ≥ 50% |

### 작은 레시피 엣지 케이스

- 필요 3개 / 보유 0개 → 부족 3/3 = 100% ≥ 50% → **제외**. (개수상 유예 구간이어도 제외 필터가 먼저 잡는다.)
- 또한 보유 0개는 2단계 후보 선정에서 이미 빠지므로 이중으로 안전.

## 정책

- **재료 정규화(별칭 사전):** 매칭 전 재료명을 정규화한다. 표기 차이는 별칭 사전으로 통일하되, 대파/파 같은 동일 취급 여부는 **기준(시드) 데이터에 따라** 결정한다. 별칭 사전은 코드가 아니라 데이터/설정으로 둔다.
- **대체 재료 금지:** 별도 검증 없이 다른 재료를 자동 대체 가능하다고 판단하지 않는다. 정규화된 이름의 **정확 일치**만 본다.
- **부족 재료 필터링:** 임박 활용 점수가 높더라도 필요한 재료가 지나치게 부족하면(제외선) 추천에서 제외한다.
- **추천 결과 설명:** 추천 레시피마다 보유 재료·부족 재료·임박 재료 활용 여부를 사용자에게 보여준다(API의 `ownedIngredients` / `missingIngredients` / `expiringIngredientsUsed`).

## 열린 항목 (추후)

- w1/w2/w3, 임박 기준일, 제외선은 목업 데이터 튜닝으로 조정 가능.
- "임박 재료 활용", "보유 일치도"의 구체 수치화 방식(개수 합/비율 등)은 구현 시 확정.
- 레시피 데이터 출처 확정 시 별칭 사전 기준 재검토.
